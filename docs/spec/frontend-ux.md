# 前端体验规格

- 状态：基础玩法、动态阵容、角色库与猜词模式已实现
- 适用范围：基础玩法兼容桌面与移动端；扩展玩法当前以 1024px 以上桌面为验收范围

## 1. 体验目标

应用的单一核心任务是让人类与多个 AI 或 4～8 个 AI 自主完成一局规则清晰、信息不泄漏、可以回看过程的“谁是卧底”。界面不是聊天软件或后台仪表盘，而是“紧凑阵容 + 聚焦角色舞台 + 随行动展开的漫画时间线”。

当前实现已经接入 DeepSeek、豆包、千问以及男、女人类形象的 5 种状态 WebP 和独立头像，路径和状态映射见 [`../notes/ASSETS.md`](../notes/ASSETS.md)。审讯室 WebP 背景和压缩 MP3 已进入前端素材目录，并由顶部设置提供纸面/审讯室切换与本地音乐开关。精细纸纹和复杂场景合成属于后续视觉工作。

### 1.1 玩家夺舍与八人阵容

- 首页标题“谁”的身份弹层同时提供男/女人类剪影和当前可用 AI 角色。选择剪影时允许填写玩家名称；选择 AI 角色时直接使用角色名称与素材，并提示该角色会从 AI 阵容中移除。
- 角色库只展示可供 AI 配置的角色，不展示男/女人类剪影。复制与编辑必须是两个独立动作，复制成功后明确提示新副本名称。
- 6～8 人紧凑席位采用“头像、最多两行名称、短状态”的纵向结构。完整动作图只在聚焦舞台展示；淘汰、思考、发言等状态通过稳定角标和边框表达。
- 1280px 桌面宽度下，8 个席位不得出现横向滚动、名称遮挡或因状态切换产生明显位移。移动端专项优化不属于本期验收范围。

## 2. 视觉方向

视觉基线来自纸面推理游戏和漫画草稿：略有抖动的墨线、克制平涂、轻纸张感、对话气泡和投票印章。首个里程碑必须形成统一设计令牌，但以下值可在实际浏览器评审后调整。

### 2.1 建议色彩令牌

| 名称 | 建议值 | 用途 |
| --- | --- | --- |
| `paper` | `#F7F3E8` | 主背景与卡片纸面 |
| `ink` | `#26231F` | 正文、描边和主要状态 |
| `blue-pencil` | `#3E6F8E` | 当前行动、链接和 AI 进行中 |
| `seal-red` | `#B74335` | 投票印章、淘汰和破坏性确认 |
| `mustard` | `#D6A93A` | 词牌、待操作和局部强调 |
| `muted-ink` | `#777066` | 次要说明和不可用状态 |

不得使用大面积渐变、玻璃拟态或通用 SaaS 蓝紫卡片风。最终颜色以可访问性对比度和项目负责人视觉确认优先。

### 2.2 字体角色

- 标题/回合标记：具有手写或漫画标题感的中文字体，使用克制，必须提供可靠系统字体回退。
- 正文/操作：高可读中文无衬线字体。
- 状态/编号：等宽或窄体字体，用于回合、票数和系统状态。

首个里程碑不得为视觉效果阻塞加载；Web 字体选择和授权在实现时确认。

### 2.3 标志性结构

可识别特征是“草稿转正”的当前分镜：AI 思考时只显示稳定尺寸的蓝铅笔草稿轮廓，合法结果通过服务端校验后在同一位置转为墨线气泡。该变化表达校验边界，不显示任何私有推理。

## 3. 顶层信息架构

应用不设置宣传首页，打开后进入“新对局”。顶层导航包含：

1. **新对局**：配置、未完成对局恢复和当前对局。
2. **模型档案**：三个模型角色的名称、三个性格标签、完整人格提示和 model ID 选择。

正常终局后额外显示当前单局的“复盘”入口（`App.tsx` 内 `topView` 轻量切换，不引路由库）。顶层导航不提供“历史复盘”，避免和单局复盘形成重复概念；当前单局支持导出脱敏 Markdown，跨局历史列表仍未实现。

## 4. 页面状态

### 4.1 新对局配置

必须包含：

- 页面标题保持“谁是卧底”的一级标题语义；其中“谁”以放大、加粗和阴影强调，并作为可点击的玩家身份配置入口。
- 点击“谁”打开“编辑玩家身份”弹层，在同一事务式交互中编辑人类名称和人物形象。名称可留空，提交时回退为“玩家”，输入上限为 12 个字符。
- 弹层提供两个人类形象选项和明确选中态；保存后名称与形象一起生效，取消、遮罩或 Esc 关闭时不写入草稿。打开后聚焦名称输入，Tab 焦点约束在弹层内，关闭后焦点返回“谁”。
- 页面中央只突出玩法入口：“经典模式”为宽大的主操作，“猜词模式”为下方较小的次操作；两者都进入阵容配置页并携带明确 `gameMode`。
- 阵容配置页选择人类参与或纯 Agent 对局、4～8 人总数、唯一 Agent 角色、简单/困难难度和派生卧底数；真实 Provider 的纯 Agent 局还必须配置请求预算。
- 人类身份在参与模式下沿用标题“谁”的名称和人物配置；观察模式不创建虚拟人类座位。

DeepSeek、豆包、千问始终作为内置角色保留；阵容也可选择已完整配置的自建角色，人类男女剪影不得用于 Agent。当前实现启动时通过 `GET /api/games/active` 自动恢复唯一活动局；普通活动局直接恢复且服务端以 `ACTIVE_GAME_EXISTS` 阻止创建第二局。若模型调用因服务或操作系统中断，对局恢复页提供“继续上一局”和“开始新局”：后者以独立无胜者原因结束旧局并回到新对局配置，不冒充主动放弃或模型失败。

### 4.2 准备阶段

- 展示四个座位和本局公开配置，不显示任何阵营。
- 人类词牌默认牌背；点击或键盘激活后翻面，再次激活隐藏。
- 翻面状态只保存在浏览器，不调用 API、不写时间线。
- 主操作为“我已记住，开始游戏”；只有该操作提交 `StartGame`。
- 刷新后仍停留准备阶段，词牌分配保持不变，牌面恢复隐藏。

### 4.3 对局主界面

基本结构：

```text
┌ 顶栏：回合 / 阶段 / 存活玩家 / 隐藏词牌按钮 ┐
├ 当前安全状态：正在行动、重试或等待玩家 ────┤
│ 分镜 1：回合开始                              │
│ 分镜 2：角色描述                              │
│ 分镜 3：角色描述                              │
│ ...                                           │
│ 当前分镜：稳定高度的草稿或正式内容            │
├ 人类操作区：仅在轮到本人时出现                ┤
└ 回到当前 / 放弃对局                           ┘
```

- 新分镜沿时间纵向追加，默认跟随当前行动。
- 用户主动向上滚动后停止自动抢回底部，并显示“回到当前”。
- 思考、重试和正式内容必须使用稳定的响应式占位尺寸，避免页面跳动。
- 历史公开分镜可以回看，但不可编辑或重新提交。
- 当人类描述、辩解或投票回合首次到来且操作区不在浏览器视口内时，页面仅将操作区定位到可见范围；已在回看历史的用户不因同一行动重复触发而被抢回。

### 4.4 人类描述/辩解

- 文本框显示 2–40 字、最多两句和禁止原词的即时提示。
- 提交按钮不可用时，输入框旁明确显示最小字数、最大字数、句数或泄词原因，避免只用灰色禁用态要求玩家猜测。
- 前端可以运行同一纯校验器提供反馈，但服务端是最终裁判。
- 服务端拒绝后保留输入供修改，但不得在时间线显示拒绝内容。
- 提交期间防止重复操作；超时不能让客户端自行判定成功或失败，应按修订号重新获取视图。

### 4.5 猜词与秘密投票

- 猜词模式中，人类可在自己的普通描述或初始投票时切换到猜词；表单包含风险说明、存活目标、1～40 字猜测词，并以第二次确认提交。
- 每名玩家每局最多猜一次。提交后立即标记已使用，不能通过刷新或切换阶段再次获得机会。
- 描述阶段立即结算；投票阶段不因先返回而提前公开或淘汰，所有人从同一冻结快照决策后统一结算。
- 进行中时间线只显示谁猜测以及成功/失败，不显示目标或猜测词；正常终局事实复盘才展示完整记录，放弃和系统终止不展示。

- 仅显示合法目标，不能自投或选择已淘汰玩家。
- 投票开始后，所有本阶段有投票资格且尚未完成的存活玩家同时使用思考状态，表达秘密选票可并行形成；已完成者恢复待机并显示“已投票”，不显示目标、理由或概率。
- 重投阶段的平票候选没有投票资格，继续保持被怀疑状态；只有参与重投且尚未完成的玩家使用思考状态。该表现不改变服务端按状态机顺序提交和统一揭票的事实规则。
- 人类提交后也只显示已完成状态。
- 全部完成后新增独立“投票揭晓”分镜，一次性展示每名玩家投给谁。
- 票数统计是揭晓分镜的派生展示，不提前显示滚动票数。

### 4.6 平票分支

- 平票分镜明确标出候选集合。
- 候选依次进入辩解分镜，沿用描述的字数、句数和泄词提示。
- 重投操作只向非候选存活玩家开放，目标只显示平票候选。
- 再次平票时显示“本轮无人淘汰”，随后进入下一轮。
- 全员最高票时直接显示“本轮无人淘汰”，不渲染无意义的辩解或重投步骤。

### 4.7 淘汰与观战

- 淘汰分镜只公布玩家被淘汰，不翻开阵营或词牌。
- 人类被淘汰且对局未结束时，显示“继续观战”和“放弃本局”。
- 继续观战后只保留普通公开视图，不能看到身份、词牌、AI 信念或理由。
- 人类不再显示描述、辩解和投票操作；AI 自动推进到终局。

### 4.8 放弃

- 进行中和淘汰后均可发起放弃。
- 必须使用明确二次确认，说明“本局不会产生阵营胜负，将保留不完整记录”。
- 确认按钮使用一致文案“放弃本局”；取消操作不产生 API 命令。
- 成功后显示“本局已放弃”，不显示平民或卧底获胜。

### 4.9 系统错误

- 自动恢复期间只显示非信息性工作/重试状态，不显示地址、请求、模型原文或可推断私有内容的错误细节；恢复耗尽后才显示脱敏错误摘要（DEC-086）。
- 重试期间保留当前分镜稳定尺寸，禁止人类重复提交同一行动。
- 达到上限后显示“本局因模型服务异常终止”，提供错误摘要、不完整事实和开始新对局入口。
- 系统异常终止不能显示“继续”或“重试本动作”。

### 4.10 正常终局

终局按四层渐进：

1. 显示平民或卧底胜利。
2. 按座位顺序自动逐张揭晓真实阵营和词牌。
3. 全部揭晓后开放确定性事实复盘。
4. 在独立区域轮询并显示异步 AI 总结；生成状态不阻塞确定性事实复盘。

复盘页标题旁显示“经典模式/猜词模式”。经典模式直接展示通用 AI 评价；猜词模式把全部猜词事实放入默认折叠的单行记录，再以“AI 猜词决策”展示一段策略总结和最多 3 个关键节点。专项只评价 AI，不评价人类；使用“合理、冒进、依据不足、错失机会”定性标签，不新增数字评分。专项生成失败但通用评价有效时显示一条局部不可用提示并继续展示通用评价。终局胜利文案使用“卧底已被淘汰”，具体淘汰方式由事实时间线和猜词记录说明。

翻牌动画只消费已持久化事实，不发送改变状态的命令。刷新或离开再进入时可以直接恢复揭晓结果，不重复生成终局。减少动态效果模式下使用无动画或弱动画自动展示。

### 4.11 连接与服务中断恢复（已实现）

- SSE 中断不足约 3 秒时保持安静重连；持续中断后以非阻塞横幅显示“连接中断，正在恢复”，不清空当前分镜、表单或本地输入。
- 客户端采用递增间隔持续重连，并提供“立即重试”；恢复后重新获取权威 `HumanGameView` 和游标，不自动刷新整页。
- 待确认的人类命令只在当前标签页 `sessionStorage` 保存稳定 `commandId` 和原负载。响应丢失时先查询权威状态；已提交则清理待确认记录，未提交才复用同一 ID 重试。
- 服务在模型调用期间中断时，恢复页明确提供“继续上一局”和“开始新对局”。前者恢复中断动作，后者以“中断后未继续”结束旧局；不得将该情况显示为模型失败。
- 已建立连接时若后台推进发生未分类程序异常，`runtime_interrupted` 事件立即触发权威同步并显示同一双选项；刷新或 SSE 重连不得绕过玩家选择自动继续。
- 数据库进入受限诊断状态时，前端只显示脱敏的本地数据异常和停止业务操作，不展示文件路径、SQL、堆栈或自动修复按钮。

## 5. 模型档案

每张身份卡展示：

- 模型角色名称。
- 三个简短性格标签。
- 完整人格提示词。
- 与其他角色相同的规则与信息边界说明。
- 当前所选 model ID 与可输入的建议控件（候选数据来自 `GET /api/models`，也允许直接手填）。

允许展示、填写并选择 model ID；`providerMode=fake`、未配置或存在活动局时禁用输入并给出提示。`openai-compatible` 模式没有角色默认值，三张卡初始显示“未配置”；即使中转站不支持 `/models`，仍可手填并保存。页面只根据 `reviewModelConfigured` 布尔值提示评测 model 缺失，不接收或展示 env 值。仍绝不展示系统控制提示、接口地址（Base URL）、密钥或请求头（继承 DEC-082/DEC-052）。三个模型角色使用 [`../notes/ASSETS.md`](../notes/ASSETS.md) 中已索引的待机素材作为身份卡默认图；加载失败时使用统一几何占位头像。

### 5.1 Agent 调试面板（已实现）

只有服务端 `AGENT_DEVELOPER_MODE=true` 时，设置区才显示“开发者模式”开关；开关默认关闭并只保存在当前标签页。服务端门禁关闭时，普通用户无法通过 DOM、Network 或浏览器开发者工具发现或读取诊断数据。

打开后增加只读面板，按“调用链、上下文、错误与恢复、复盘调度”四个视图展示 `gameId -> commandId -> actionId -> attemptId`、上下文类型与边界校验、模型耗时、重试/修复、结果分类、熔断和复盘队列状态。面板不得提供状态修改或重新执行付费调用的操作。

面板内提供独立的“记录完整上下文”开关，默认关闭；开启前说明完整 Prompt/响应包含本局私有信息，状态只在当前服务会话有效并在服务重启后关闭。完整记录按条目折叠，每次展开前再次确认；即使展开也不得显示 Base URL、Key 或请求头。

## 6. 响应式布局

- 移动端采用单列漫画流，操作区贴近当前分镜但不得遮挡内容。
- 桌面端可以使用窄侧栏展示存活玩家和回合状态，主漫画流保持适合阅读的最大宽度。
- 角色图使用统一安全裁切区；占位素材与最终素材必须能在相同容器替换。
- 不以悬停作为唯一信息来源；触控设备必须完成全部操作。
- 输入法弹出、SSE 状态变化和气泡文本增长不得导致主要操作跳出可见区域。

## 7. 无障碍与动效

- 所有交互可键盘操作，并提供清晰焦点态。
- 词牌必须使用按钮语义，并通过可访问文本说明当前“已隐藏/已显示”。
- 颜色不能作为存活、淘汰、当前行动或错误的唯一标识。
- SSE 新内容使用适度的 live region；连续 AI 分镜不得造成屏幕阅读器刷屏。
- 遵守 `prefers-reduced-motion`：关闭翻转、自动平滑滚动和草稿转正动画，但保留状态变化。
- 动画不得阻塞操作或成为事实提交条件。

## 8. 文案约定

按钮描述玩家可预期的结果，例如“开始新对局”“我已记住，开始游戏”“提交描述”“确认投票”“继续观战”“放弃本局”“回到当前”。错误文案说明发生了什么和下一步，不使用模糊的“出错了”或拟人化道歉。

同一操作在按钮、进度和结果提示中保持同一词汇。界面称“词牌”“阵营”“描述”“辩解”“投票”“复盘”，不混用“身份词”“聊天消息”等近义名称。

## 9. 视觉与媒体收口切片

### 9.1 BGM

- 当前 Web 音源为 `apps/web/src/assets/audio/game-bgm.mp3`，通过 Vite URL 导入，不把音频内容写入状态机、REST 或 SSE；仓库不再保留重复的根目录原始副本或未压缩 WAV。
- BGM 只在 `in_progress` 或 `awaiting_spectator` 播放；准备、新建、模型档案、正常终局和放弃终局暂停并归零。
- 默认关闭并遵守浏览器自动播放限制；用户开启后若恢复进行中对局时播放被拦截，下一次点击/按键或点击音乐按钮后继续尝试。
- 顶部工具栏提供可键盘操作的“背景音乐：开/关”按钮，使用 `aria-pressed` 和文字状态；关闭时立即暂停，开启时在允许阶段播放。
- 音乐偏好保存在本地浏览器，不进入对局事件；加载或播放失败不得影响游戏，并以非打断式状态说明。

### 9.2 背景选择

- 顶部工具栏提供“纸面背景”和“审讯室背景”两个互斥选择，使用可访问的 radiogroup 语义。
- 纸面背景沿用当前米色横线纸；审讯室背景使用 `sceneAssets.interrogationRoom`，增加低对比遮罩保证文字和控件可读。
- 背景偏好仅保存在当前浏览器，不进入服务端、对局事件或 Agent 上下文。
- 移动端使用同一审讯室图片的中心焦点裁切；背景资源失败时自动降级为纸面背景。

### 9.3 角色素材整理

- `character-assets.ts` 是角色路径与状态映射的单一入口；五个角色统一 `idle/thinking/speaking/suspected/eliminated`。
- 新对局剪影选择直接展示男、女人类待机素材，不再使用几何 CSS 占位剪影。
- 图片必须使用明确替代文本；加载失败时保留角色首字占位，不影响选择和对局操作。
- 当前动作图已统一为 512×640 WebP，头像为 256×256 WebP；转换与检查由 `scripts/optimize-assets.py` 复现，且不改变 `CharacterKey` 和五状态组件接口。

### 9.4 视觉与无障碍收口

- 所有按钮、输入、文本域、选择器和自定义单选项使用一致且清晰的 `:focus-visible`。
- 点击/触控目标最小高度 44px；选择态除颜色外同时使用边框、内阴影或文字状态。
- 音乐、背景选择和主导航在窄屏允许换行，不遮挡内容。
- 动画继续遵守 `prefers-reduced-motion`；音频开关与减少动态效果互相独立。
- 状态更新使用克制的 `role=status`/`aria-live`，错误使用 `role=alert`；不得因装饰背景改变信息隔离或 DOM 私有字段边界。
