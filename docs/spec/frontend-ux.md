# 前端体验规格

- 状态：首个里程碑已实现基线
- 适用范围：当前桌面与移动端实现；后续视觉润色

## 1. 体验目标

应用的单一核心任务是让一名人类与三名 AI 完成一局规则清晰、信息不泄漏、可以回看过程的“谁是卧底”。界面不是聊天软件或后台仪表盘，而是一条随行动向下展开的动态漫画分镜。

当前实现已经接入 DeepSeek、豆包、千问以及男、女人类形象的 5 种状态素材，路径和状态映射见 [`../notes/ASSETS.md`](../notes/ASSETS.md)。对局背景已经复制到前端素材目录，但当前组件尚未消费；背景音乐仍只保存在原始素材包中，尚未接入播放器。精细纸纹、场景合成和音频控制属于后续视觉切片。

## 2. 视觉方向

视觉基线来自纸面推理游戏和漫画草稿：略有抖动的墨线、克制平涂、轻纸张感、对话气泡和投票印章。首个里程碑必须形成统一设计令牌，但以下值可在实际浏览器评审后调整。

### 2.1 建议色彩令牌

| 名称 | 建议值 | 用途 |
| --- | --- | --- |
| `paper` | `#F7F3E8` | 主背景与卡片纸面 |
| `ink` | `#26231F` | 正文、描边和主要状态 |
| `blue-pencil` | `#3E6F8E` | 当前行动、链接和 AI 进行中 |
| `seal-red` | `#B74335` | 投票印章、淘汰和破坏性确认 |
| `mustard` | `#D6A93A` | 词牌、待操作和局部强调 |
| `muted-ink` | `#777066` | 次要说明和不可用状态 |

不得使用大面积渐变、玻璃拟态或通用 SaaS 蓝紫卡片风。最终颜色以可访问性对比度和项目负责人视觉确认优先。

### 2.2 字体角色

- 标题/回合标记：具有手写或漫画标题感的中文字体，使用克制，必须提供可靠系统字体回退。
- 正文/操作：高可读中文无衬线字体。
- 状态/编号：等宽或窄体字体，用于回合、票数和系统状态。

首个里程碑不得为视觉效果阻塞加载；Web 字体选择和授权在实现时确认。

### 2.3 标志性结构

可识别特征是“草稿转正”的当前分镜：AI 思考时只显示稳定尺寸的蓝铅笔草稿轮廓，合法结果通过服务端校验后在同一位置转为墨线气泡。该变化表达校验边界，不显示任何私有推理。

## 3. 顶层信息架构

应用不设置宣传首页，打开后进入“新对局”。顶层导航包含：

1. **新对局**：配置、未完成对局恢复和当前对局。
2. **模型档案**：三个模型角色的名称、三个性格标签、完整人格提示和 model ID 选择。
3. **历史复盘**：已完成、已放弃和异常终止对局。

当前已实现顶层功能为"新对局/当前对局"与"模型档案"（`App.tsx` 内 `topView` 轻量切换，不引路由库）。历史复盘列表、Markdown 导出和异步 AI 总结尚未实现；终局事实目前从当前/最近一局的终局页面进入，不得把规划中的导航写成现有能力。

## 4. 页面状态

### 4.1 新对局配置

必须包含：

- 人类名称，可留空，输入时 1 至 12 个字符。
- 两个人类剪影选项，具备可见选中态和键盘操作。
- 简单/困难难度选择。
- “开始新对局”操作。

三个 AI 角色固定显示，不能让玩家误以为可选择阵容。当前实现启动时通过 `GET /api/games/active` 自动恢复唯一活动局；存在活动局时不会显示新建表单，服务端也以 `ACTIVE_GAME_EXISTS` 阻止创建第二局。当前尚未实现“放弃旧局并开始新局”的合并快捷操作，玩家需进入恢复的对局后使用既有放弃流程。

### 4.2 准备阶段

- 展示四个座位和本局公开配置，不显示任何阵营。
- 人类词牌默认牌背；点击或键盘激活后翻面，再次激活隐藏。
- 翻面状态只保存在浏览器，不调用 API、不写时间线。
- 主操作为“我已记住，开始游戏”；只有该操作提交 `StartGame`。
- 刷新后仍停留准备阶段，词牌分配保持不变，牌面恢复隐藏。

### 4.3 对局主界面

基本结构：

```text
┌ 顶栏：回合 / 阶段 / 存活玩家 / 隐藏词牌按钮 ┐
├ 当前安全状态：正在行动、重试或等待玩家 ────┤
│ 分镜 1：回合开始                              │
│ 分镜 2：角色描述                              │
│ 分镜 3：角色描述                              │
│ ...                                           │
│ 当前分镜：稳定高度的草稿或正式内容            │
├ 人类操作区：仅在轮到本人时出现                ┤
└ 回到当前 / 放弃对局                           ┘
```

- 新分镜沿时间纵向追加，默认跟随当前行动。
- 用户主动向上滚动后停止自动抢回底部，并显示“回到当前”。
- 思考、重试和正式内容必须使用稳定的响应式占位尺寸，避免页面跳动。
- 历史公开分镜可以回看，但不可编辑或重新提交。

### 4.4 人类描述/辩解

- 文本框显示 2–40 字、最多两句和禁止原词的即时提示。
- 前端可以运行同一纯校验器提供反馈，但服务端是最终裁判。
- 服务端拒绝后保留输入供修改，但不得在时间线显示拒绝内容。
- 提交期间防止重复操作；超时不能让客户端自行判定成功或失败，应按修订号重新获取视图。

### 4.5 秘密投票

- 仅显示合法目标，不能自投或选择已淘汰玩家。
- AI 依次显示“正在投票”“已完成投票”，不显示目标、理由或概率。
- 人类提交后也只显示已完成状态。
- 全部完成后新增独立“投票揭晓”分镜，一次性展示每名玩家投给谁。
- 票数统计是揭晓分镜的派生展示，不提前显示滚动票数。

### 4.6 平票分支

- 平票分镜明确标出候选集合。
- 候选依次进入辩解分镜，沿用描述的字数、句数和泄词提示。
- 重投操作只向非候选存活玩家开放，目标只显示平票候选。
- 再次平票时显示“本轮无人淘汰”，随后进入下一轮。
- 全员最高票时直接显示“本轮无人淘汰”，不渲染无意义的辩解或重投步骤。

### 4.7 淘汰与观战

- 淘汰分镜只公布玩家被淘汰，不翻开阵营或词牌。
- 人类被淘汰且对局未结束时，显示“继续观战”和“放弃本局”。
- 继续观战后只保留普通公开视图，不能看到身份、词牌、AI 信念或理由。
- 人类不再显示描述、辩解和投票操作；AI 自动推进到终局。

### 4.8 放弃

- 进行中和淘汰后均可发起放弃。
- 必须使用明确二次确认，说明“本局不会产生阵营胜负，将保留不完整记录”。
- 确认按钮使用一致文案“放弃本局”；取消操作不产生 API 命令。
- 成功后显示“本局已放弃”，不显示平民或卧底获胜。

### 4.9 系统错误

- 第一次自动重试开始即显示错误类别和“第 n/3 次重试”，不显示地址、请求或模型原文。
- 重试期间保留当前分镜稳定尺寸，禁止人类重复提交同一行动。
- 达到上限后显示“本局因模型服务异常终止”，提供错误摘要、不完整事实和开始新对局入口。
- 系统异常终止不能显示“继续”或“重试本动作”。

### 4.10 正常终局

终局按四层渐进：

1. 显示平民或卧底胜利。
2. 按座位顺序自动逐张揭晓真实阵营和词牌。
3. 全部揭晓后开放确定性事实复盘。
4. 后续里程碑在独立区域显示异步 AI 总结。

翻牌动画只消费已持久化事实，不发送改变状态的命令。刷新或离开再进入时可以直接恢复揭晓结果，不重复生成终局。减少动态效果模式下使用无动画或弱动画自动展示。

## 5. 模型档案

每张身份卡展示：

- 模型角色名称。
- 三个简短性格标签。
- 完整人格提示词。
- 与其他角色相同的规则与信息边界说明。
- 当前所选 model ID 与可选 model 下拉（数据来自 `GET /api/models`，DEC-085）。

允许展示并选择 model ID；`providerMode=fake`、未配置或存在活动局时禁用选择并给出提示。仍绝不展示系统控制提示、接口地址（Base URL）、密钥或请求头（继承 DEC-082/DEC-052）。三个模型角色使用 [`../notes/ASSETS.md`](../notes/ASSETS.md) 中已索引的待机素材作为身份卡默认图；加载失败时使用统一几何占位头像。

## 6. 响应式布局

- 移动端采用单列漫画流，操作区贴近当前分镜但不得遮挡内容。
- 桌面端可以使用窄侧栏展示存活玩家和回合状态，主漫画流保持适合阅读的最大宽度。
- 角色图使用统一安全裁切区；占位素材与最终素材必须能在相同容器替换。
- 不以悬停作为唯一信息来源；触控设备必须完成全部操作。
- 输入法弹出、SSE 状态变化和气泡文本增长不得导致主要操作跳出可见区域。

## 7. 无障碍与动效

- 所有交互可键盘操作，并提供清晰焦点态。
- 词牌必须使用按钮语义，并通过可访问文本说明当前“已隐藏/已显示”。
- 颜色不能作为存活、淘汰、当前行动或错误的唯一标识。
- SSE 新内容使用适度的 live region；连续 AI 分镜不得造成屏幕阅读器刷屏。
- 遵守 `prefers-reduced-motion`：关闭翻转、自动平滑滚动和草稿转正动画，但保留状态变化。
- 动画不得阻塞操作或成为事实提交条件。

## 8. 文案约定

按钮描述玩家可预期的结果，例如“开始新对局”“我已记住，开始游戏”“提交描述”“确认投票”“继续观战”“放弃本局”“回到当前”。错误文案说明发生了什么和下一步，不使用模糊的“出错了”或拟人化道歉。

同一操作在按钮、进度和结果提示中保持同一词汇。界面称“词牌”“阵营”“描述”“辩解”“投票”“复盘”，不混用“身份词”“聊天消息”等近义名称。

## 9. 视觉与媒体收口切片

### 9.1 BGM

- 原始母带为 `素材/bgm.wav`，Web 通过 Vite URL 导入，不把音频内容写入状态机、REST 或 SSE。
- BGM 只在 `in_progress` 或 `awaiting_spectator` 播放；准备、新建、模型档案、正常终局和放弃终局暂停并归零。
- 默认启用但遵守浏览器自动播放限制；若恢复进行中对局时播放被拦截，用户下一次点击/按键或点击音乐按钮后继续尝试。
- 顶部工具栏提供可键盘操作的“背景音乐：开/关”按钮，使用 `aria-pressed` 和文字状态；关闭时立即暂停，开启时在允许阶段播放。
- 音乐偏好保存在本地浏览器，不进入对局事件；加载或播放失败不得影响游戏，并以非打断式状态说明。

### 9.2 背景选择

- 顶部工具栏提供“纸面背景”和“审讯室背景”两个互斥选择，使用可访问的 radiogroup 语义。
- 纸面背景沿用当前米色横线纸；审讯室背景使用 `sceneAssets.interrogationRoom`，增加低对比遮罩保证文字和控件可读。
- 背景偏好仅保存在当前浏览器，不进入服务端、对局事件或 Agent 上下文。
- 移动端使用同一审讯室图片的中心焦点裁切；背景资源失败时自动降级为纸面背景。

### 9.3 角色素材整理

- `character-assets.ts` 是角色路径与状态映射的单一入口；五个角色统一 `idle/thinking/speaking/suspected/eliminated`。
- 新对局剪影选择直接展示男、女人类待机素材，不再使用几何 CSS 占位剪影。
- 图片必须使用明确替代文本；加载失败时保留角色首字占位，不影响选择和对局操作。
- 本切片保持当前 PNG，不在缺少可验证转码工具时伪报 WebP 完成；后续压缩不得改变 `CharacterKey` 和组件接口。

### 9.4 视觉与无障碍收口

- 所有按钮、输入、文本域、选择器和自定义单选项使用一致且清晰的 `:focus-visible`。
- 点击/触控目标最小高度 44px；选择态除颜色外同时使用边框、内阴影或文字状态。
- 音乐、背景选择和主导航在窄屏允许换行，不遮挡内容。
- 动画继续遵守 `prefers-reduced-motion`；音频开关与减少动态效果互相独立。
- 状态更新使用克制的 `role=status`/`aria-live`，错误使用 `role=alert`；不得因装饰背景改变信息隔离或 DOM 私有字段边界。

## 10. 当前实现边界

必须保持：统一令牌、响应式分镜结构、准备词牌交互、完整操作状态、AI 与人类角色素材状态映射、秘密投票节奏、终局揭晓结构和减少动态效果支持。

本切片完成后：审讯室背景可由用户与默认纸面背景切换；BGM 具备浏览器本地开关和安全生命周期；新建对局使用真实人类剪影素材。WebP 压缩、纸张纹理深化、复杂动画、历史列表和异步 AI 总结区仍属于后续工作。
