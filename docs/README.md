# 项目文档导航

本目录按用途分为任务、注意事项、验收标准、工程规格和历史记录五类。请从本页进入，不要通过聊天归档推断当前行为。

## 推荐阅读顺序

1. [任务台账](tasks/TASKS.md)：当前做到哪里、下一步做什么。
2. [里程碑检查清单](tasks/milestone-1-checklist.md)：当前任务的细分检查点与完成状态。
3. [工程规格](spec/README.md)：系统必须如何实现。
4. [验收标准](acceptance/README.md)：产品范围、切片合同和测试门禁。
5. [注意事项](notes/README.md)：协作、决策和素材约束。
6. [历史记录](history/README.md)：负责人命令、已完成证据和交流语境。

## 事实源优先级

出现不一致时，依次以以下内容为准：

1. 当前有效的[产品需求与验收标准](acceptance/REQUIREMENTS.md)。
2. 当前有效的[工程规格](spec/README.md)。
3. 当前实施的[任务台账](tasks/TASKS.md)与 checklist。
4. 已确认的[决策与注意事项](notes/README.md)。
5. [开发完成记录](history/PROJECT_LOG.md)。
6. [交流归档](history/chat/INDEX.md)。

历史记录只用于追溯，不覆盖较新的结构化契约。

## 实时更新规则

- 新任务：先写入任务台账和 checklist，再开始实现。
- 开始任务：先说明目标，将状态改为“进行中”。
- 完成检查点：立即勾选 checklist，并附测试、浏览器或文件证据。
- 完成任务：只有门禁全部通过后才改为“已完成”，并更新开发记录。
- 产品行为变化：先由负责人确认，再更新需求与规格。
- 重大架构变化、Git 提交/推送、付费真实模型调用和破坏性数据操作继续遵守协作门禁。
