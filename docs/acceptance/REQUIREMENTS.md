# 需求记录

## 当前阶段

项目已完成首版规则、总体架构和首个里程碑确认，可以进入功能开发阶段。

## 已确认要求

- 项目采用全栈开发方式。
- 开发过程允许进行多轮迭代。
- 关键分支和重大决策由项目负责人把关。
- 保留核心命令、开发过程、关键决策和较大版本变更，便于复盘分析。
- 文档和代码注释尽可能使用中文。

## 产品目标

从零开发一个可在本地运行、可完整游玩的 AI 版“谁是卧底”小游戏，并最终以 GitHub 仓库形式交付。

## 核心验收要求

- 至少包含一名人类玩家和三名 AI 玩家，并能完成一整局游戏。
- AI 的描述和投票必须由真实模型生成。
- 每名 AI 只能获得自己的身份、自己的词语以及当时已经公开的信息。
- 游戏包含描述、投票、淘汰、胜负判断和赛后复盘。
- 每名 AI 在对局过程中维护私有猜测：自己属于哪个阵营、敌对阵营身份词可能是什么，以及作出判断的理由。
- 敌对阵营身份词允许同时存在多个候选，每个候选应包含置信度和判断依据。
- 复盘展示 AI 猜测随公开信息变化的过程，但对局中不得把私有猜测泄露给其他玩家。
- 具备基本错误处理、本地启动方式和可重复的验证方式。
- README 说明启动方式、核心设计、信息隔离、AI 工具的使用与验收，以及已知问题。
- 保留便于分享、讨论和复盘的迭代记录。

## 交互与美术方向

- 前端采用简洁、轻量的 2D 手绘游戏风格。
- 建立项目内的最小素材库，至少覆盖角色、表情、身份卡、投票标记、场景物件和基础 UI 图形。
- 缺少风格统一的角色素材时，可在确认提示词和授权策略后使用 AI 生图补充。

## 首版规则状态

- 首版核心玩法、胜负条件、Agent 信息边界、模型接入、复盘方式和总体技术架构已经确认。
- 实现过程中如发现新的产品歧义，按协作规范一次提出一个决策点，并由项目负责人确认后继续。

## 已确认游戏规则

- 所有玩家只知道自己的词牌，不知道自己的真实阵营。
- 所有玩家可以看到哪些玩家已经淘汰。
- 玩家淘汰时不公开其真实阵营和词牌。
- 完整身份与词牌分配仅由服务端裁判保存，游戏结束后用于复盘。
- 基础玩法中，卧底被淘汰时平民获胜；场上只剩两名玩家且卧底仍存活时卧底获胜。
- 首轮随机确定发言顺序，后续每轮沿座位顺序轮换起始玩家，淘汰玩家自动跳过。
- 所有存活玩家独立秘密投票，所有票提交前互不可见；前端按角色逐个展示“正在投票”和“已完成投票”的非信息性状态，全部完成后统一公开每名玩家的投票目标。
- 每名 AI 投票时保存不可修改的信念快照和投票理由，供赛后复盘使用。
- 最高票平票时，平票候选各进行一次简短辩解，随后由未进入平票的其他存活玩家针对平票候选重新秘密投票；平票候选不参与重投。
- 辩解属于新的公开信息，参与重投的 AI 可以据此更新私有信念。
- 重新投票后仍然平票，则本轮无人淘汰并进入下一轮。
- 如果所有存活玩家都是最高票平票候选，因不存在可参与重投的其他玩家，本轮直接无人淘汰并进入下一轮，不进行候选辩解或零人重投。
- 公开描述和公开辩解均限制为 2 至 40 个字符、最多两句，不得包含自己的词牌原词。
- 不对不同玩家、不同轮次或描述与辩解之间的相同文本执行服务端重复拦截；避免机械复读只作为 AI 提示词中的表达质量要求。
- AI 描述和辩解提示词必须要求模型在返回前检查是否泄露原词。
- AI 描述或辩解生成后由服务端再次进行确定性校验；发现原词、长度或句数违规时作废并要求模型重新组织。
- 违规描述不得公开，也不得作为其他 Agent 的可见信息。
- 人类玩家与 AI 使用相同的服务端原词校验，前端校验仅用于即时提示，不能替代服务端校验。
- 原词校验先执行 Unicode 规范化、英文大小写统一，并移除空格和常见标点；规范化结果连续包含完整词牌原词时判定泄露。
- 同音字、拼音、隐喻、拆字解释和其他语义近似不由确定性程序判为可处罚的原词泄露。
- 同一发言机会首次泄露词牌原词时，拦截该描述并允许玩家重新发言一次。
- 重新发言仍泄露原词时，公开报告“该玩家违反游戏规则”，强制该玩家退出对局并立即进行胜负判定。
- 只有直接泄露自己的词牌原词属于可导致强制退出的游戏违规。
- 长度和句数不合规则属于格式错误；模型超时、限流、网络或无效结构化输出属于系统错误，均不得处罚玩家或改变胜负。
- 人类格式错误时阻止提交并允许继续修改；AI 格式或系统错误按独立的恢复流程处理。
- AI 只在行动节点更新私有信念，包括发言前、投票前、平票辩解前和重新投票前。
- 信念更新与对应的描述、辩解或投票应尽量在同一次结构化模型调用中完成，并将返回的信念作为该动作的历史快照。
- 首版固定为一名人类玩家、三名 AI 玩家、一名卧底和三名平民。
- 卧底席位在四名玩家中等概率随机分配，人类与三个 AI 均可能成为卧底；分配结果不直接告知任何玩家。
- 随机过程支持在测试中注入固定种子，以复现任意身份与词牌分配。
- 首版创建对局时只接受固定四人配置，但核心游戏状态、座位、发言、投票和事件结构不得硬编码玩家数量。
- 后续可增加人数选择和多卧底规则；首版暂不实现对应界面和身份比例。
- AI Agent 以不同厂商或不同模型作为角色身份，角色配置包含显示信息、模型标识和简短基础提示词。
- 每名 Agent 可以使用不同模型；游戏引擎不得依赖具体厂商、模型名称或固定 Agent 数量。
- 所有 Agent 共用同一个 OpenAI 兼容中转站、基础地址、认证密钥和模型客户端；每个角色只通过模型 ID 区分。
- 中转地址和密钥只能通过服务端本地环境变量提供，不得写入代码、仓库、数据库、日志、浏览器或复盘。
- 模型角色的预设性格保持简短，不对厂商或模型能力作未经验证的事实断言。
- 对局内直接使用真实模型简称作为 AI 玩家名，不显示额外的厂商或型号标签。
- 对局外提供模型身份卡，每张卡展示模型名称、三个性格标签、对应提示词，以及当前所选 model ID 与可选 model 下拉（DEC-085）。
- 人格提示词与负责规则、信息隔离和结构化输出的系统提示词分层维护。
- 身份卡完整展示该模型角色的简短人格提示词，不展示系统控制提示词。
- 系统控制提示词的可审查模板保存在代码和开发文档中，但不得包含任何对局私有数据或密钥。
- 首版固定使用 `DeepSeek`、`豆包`、`千问` 三个 AI 模型身份，不提供座位阵容选择界面；但允许在模型档案界面为每个固定角色选择并持久化其 model ID（DEC-085 替代 DEC-018/DEC-020 中"界面不可选 model"的部分）。可下发并持久化的仅为 model ID；Base URL、API Key、请求头与完整模型响应绝不下发或落库。
- 三个模型角色共享完全相同的游戏规则、信息边界、推理任务和结构化输出要求。
- 每个模型只增加简短的轻人格提示词，用于区分表达风格和轻微判断倾向，不得改变规则或获得额外信息。
- 首版使用项目内置且经过人工筛选的词语对，开局时由服务端随机抽取。
- 词库以仓库内独立 JSON 文件作为版本化内容事实源，服务端使用共享 Zod Schema 校验后导入或同步到 SQLite。
- JSON 中的词组使用稳定唯一 ID；更新或停用词组不得破坏历史对局对原词组快照的引用。
- 首版不提供词库管理后台，也不把用户本地 SQLite 文件作为 Git 中的词库事实源。
- 首版不使用模型动态生成词语，也不允许唯一的人类玩家自定义本局词语对。
- 每组词语对固定标注平民词和卧底词，开局时不随机交换阵营归属。
- 词库至少提供简单和困难两档；简单词语具有更多直观、可公开描述的特征，困难词语更难在不泄露原词的情况下准确描述。
- 首版内置词库共 30 组，简单和困难各 15 组；每组均经过人工筛选后才能启用。
- 开局前由人类玩家选择简单或困难难度，服务端每局从该难度下全部已启用词语对中独立随机抽取，不参考历史对局，也不设置连续重复保护或洗牌袋。
- 本局难度写入对局配置和复盘记录。
- 第一轮所有存活玩家完成描述后立即进入秘密投票，不设置免投票观察轮。
- 正式对局不设置最大回合数；未满足胜负条件时继续下一轮，不因轮数判定平局或随机淘汰。
- 自动化测试可以设置执行次数保护，但不得影响正式游戏规则。
- 人类玩家可以主动放弃进行中的对局，执行前必须二次确认。
- 人类玩家被淘汰并选择继续观战后，仍只能查看对局公开信息；其他玩家的真实阵营、词牌、AI 私有信念和投票理由统一在正常终局后揭晓。
- 选择继续观战时，剩余 AI 自动推进对局；选择退出时沿用主动放弃规则，不产生阵营胜负。
- 放弃对局不触发阵营胜负判断；对局状态标记为“已放弃”，并保留截至退出时的不完整复盘。
- 对局按已完成事件自动保存，包括合法描述、信念快照、投票、淘汰、回合切换和终局状态。
- 重新进入时若存在未完成对局，由人类玩家选择继续对局，或放弃旧对局并开始新对局。
- 放弃未完成对局时沿用主动放弃规则，不产生阵营胜负并保留不完整复盘。
- 赛后复盘包含由程序生成的确定性事实时间线，以及由独立复盘 Agent 生成的全局分析。
- 复盘 Agent 可以读取终局后的完整身份、词牌、公开事件和 AI 私有信念历史。
- AI 复盘总结必须与事实时间线分开展示，不能覆盖、修改或伪造原始对局记录。
- 复盘 Agent 使用独立的模型 ID、调用上下文和提示词，但复用统一中转站及其认证配置；可以指定参赛模型之一，也可以指定第四个模型 ID。
- 复盘模型可以单独替换；替换不得影响参赛 Agent 配置、游戏状态和历史事实记录。
- 复盘中记录实际使用的复盘模型标识，但不记录密钥和敏感接口地址。
- 终局展示按“结果公布、身份与词牌揭晓、确定性事实复盘、异步 AI 总结”分阶段进行。
- 正常终局先显示平民或卧底胜利；主动放弃和系统异常终止只显示对应状态，不生成阵营胜负。
- 身份与词牌揭晓按座位顺序自动逐张翻开，玩家无需点击；全部揭晓后再开放事实复盘入口。
- 自动翻牌只控制前端呈现，终局事实在动画开始前已经持久化，刷新或动画中断不得改变揭晓结果。
- AI 复盘总结异步生成并与事实区域分开展示；玩家无需等待总结即可查看事实或开始新对局。
- 终局后自动创建异步复盘任务，事实结果保存完成后立即允许玩家开始新对局，不等待 AI 总结生成。
- 异步复盘任务必须持久化状态；本地服务重启后可以恢复未完成任务，不能只保存在进程内存中。
- 复盘生成失败不影响终局事实和新对局，历史复盘页面提供失败状态及重新生成能力。
- 模型调用调度以实时对局为高优先级，尚未开始的复盘任务不得阻塞描述、投票或辩解调用。
- 已发出的复盘模型请求允许完成，不为抢占资源而取消；后台最多同时执行一个复盘任务。
- 首版统一通过 OpenAI 兼容中转接口调用所有参赛模型和复盘模型。
- DeepSeek、豆包、千问只通过独立模型 ID 区分，共用同一中转地址、认证、模型客户端、超时、错误映射与日志机制。
- 首版不实现三家厂商的原生接口或 SDK。
- 模型提示词要求以约定 JSON 结构返回信念、描述、投票和理由，服务端使用 Zod 校验字段、类型和取值范围。
- 首次结构化输出错误时允许一次格式修复请求；再次失败则标记为系统错误，并进入统一的系统错误重试流程，不处罚 Agent。
- 模型网络、超时、限流、服务端错误或结构修复后仍失败时，从首次重试开始立即向玩家显示脱敏错误类型和进度，并对当前行动最多自动重试三次；每次重试前固定等待 2 秒。
- 初始调用加三次自动重试仍失败时，对局自动标记为“系统异常终止”，不判定阵营胜负，不记为玩家放弃，并保留不完整事实复盘。
- “系统异常终止”是不可恢复终局，不能从失败行动继续；玩家可以查看错误摘要和不完整复盘，并开始新对局。
- 原生 JSON Schema 响应格式只能作为单模型可选优化，不作为统一中转接口的必要能力。
- Agent 的主要推理顺序为：更新多个异阵营词候选，比较公开描述与候选词的接近程度，推导各存活玩家的卧底概率，再作出投票。
- 信念快照同时保存异阵营词候选、候选置信度、玩家身份概率、判断依据和最终行动。
- 玩家身份概率包含 Agent 自己；概率总和由本局配置的卧底人数决定，不得硬编码为 1。
- 首版一名卧底时存活玩家概率总和为 1；未来多卧底模式下总和等于本局卧底人数。
- 卧底人数属于公开对局配置，所有玩家和 Agent 均可获知；具体阵营分配仍由服务端保密。
- 每名存活玩家必须投给另一名存活玩家，不允许自投或弃票。
- Agent 对自己的身份概率可以高于其他玩家，但不能因此选择自己作为投票目标。
- 全部秘密投票完成后，公开每名玩家的投票目标，公开投票关系进入后续轮次的公共信息。
- 投票理由、身份概率和异阵营词候选在对局中保持私有，只在终局复盘中展示。
- AI 生成公开行动期间展示角色化思考动画和非信息性状态，不流式展示模型原始输出或私有信念。
- 模型结果完成结构、长度、句数和原词等全部服务端校验后，才一次性公开合法内容。
- 重新生成期间继续保持思考状态，任何失败内容不得呈现给其他玩家。
- 人类玩家的词牌默认显示牌背，点击后翻开，再次点击恢复隐藏；系统不得自动公开词牌。
- 对局创建并完成身份与词牌分配后先进入准备状态；人类查看词牌并点击“我已记住，开始游戏”后，第一轮才正式开始并允许 AI 自动推进。
- 本地翻牌行为不属于游戏公开事件，不写入 Agent 上下文。
- 对局主界面采用纯 2D 手绘动态漫画分镜，不使用圆桌或 3D 舞台。
- 描述、辩解、投票揭晓和淘汰分别形成可识别的漫画分镜；当前角色通过构图、表情和对话气泡突出。
- AI 思考阶段使用草稿线等轻量动画，但不展示私有推理；校验通过的公开内容才写入正式分镜。
- 赛后事实复盘复用对局漫画时间线，并在对应行动处展开私有信念与理由。
- 漫画分镜按时间连续纵向追加，新行动开始时默认自动滚动到当前分镜。
- 玩家主动向上回看历史时，系统不得强制抢回滚动位置，应提供“回到当前”操作。
- 思考、生成和正式内容状态使用稳定的响应式尺寸，避免动态内容导致页面跳动。
- 五个角色（DeepSeek、豆包、千问和男、女人类形象）当前均具备待机、思考、发言、被怀疑和被淘汰五种项目专用素材，已接入准备页与对局页；文件与状态映射以 `docs/notes/ASSETS.md` 为准。
- 角色素材已直接接入；词牌、投票标记、气泡、分镜和通用 UI 由 CSS/SVG/HTML 实现。审讯室背景已复制到前端但尚未渲染，背景音乐尚未接入。
- 角色素材采用统一画布、透明背景和适合响应式裁切的构图，不为每条发言动态生成图片。
- 人类玩家开局时从两个性别剪影中二选一，选择只保存在本局配置中。
- 人类剪影与模型角色使用一致的手绘线条体系，通过姿势、描边、气泡和印章区分输入、发言、被怀疑和淘汰状态。
- 人类玩家可以填写 1 至 12 个字符的显示名称，未填写时默认使用“玩家”。
- 显示名称只用于本局玩家列表、漫画气泡和复盘，不建立账户或跨局个人档案。
- 应用不设置宣传首页，打开后默认进入“新对局”配置视图。
- 顶层主要视图为“新对局”“模型档案”“历史复盘”。
- 新对局视图包含人类名称、性别剪影、难度和开始操作；存在未完成对局时优先提供继续或放弃选项。
- 模型档案展示三名模型角色身份卡；历史复盘展示已完成和已放弃对局。
- 每局历史复盘支持导出单个 Markdown 文件，用于阅读、分享和验收。
- 导出内容包含对局配置、模型阵容、身份与词牌、公开时间线、Agent 信念变化、投票理由、错误摘要和 AI 复盘总结。
- 导出文件不得包含 API 密钥、敏感中转地址、被拦截的违规原文或无必要的完整模型原始响应。
- 前端采用 React、Vite 和 TypeScript，服务端采用 Fastify 和 TypeScript。
- 数据持久化采用 SQLite 与 Drizzle ORM，前后端通过共享 TypeScript/Zod 包统一类型和数据校验。
- 项目使用 pnpm workspace 组织，提供单一开发命令同时启动前后端。
- 对局使用不可变事件日志记录已确认动作，同时维护当前状态快照用于快速读取和恢复。
- 事件追加与状态快照更新必须在同一数据库事务中完成，避免事实记录与运行状态不一致。
- 漫画时间线、事实复盘、Markdown 导出和信息边界审计以事件日志为事实来源。
- 游戏流程由共享包中的自定义强类型状态机控制，阶段至少覆盖描述、投票、平票辩解、重新投票、终局和放弃。
- 状态转换实现为不依赖数据库、模型或网络的纯函数，输入当前状态和命令，输出新状态与待持久化事件。
- API、模型编排和数据访问层不得绕过状态机直接修改游戏阶段或胜负结果。
- 人类玩家命令通过 REST API 提交，服务端通过 SSE 向前端推送 AI 思考状态和已确认的对局事件。
- 轮到 AI 行动时由服务端自动推进，校验通过后按顺序发布分镜事件；轮到存活人类行动时暂停等待输入。
- 人类淘汰并选择继续观战后，剩余 AI 自动连续推进到终局，无需逐步点击。
- SSE 不传输模型原始输出、私有信念或尚未统一揭晓的投票目标；只有允许公开的状态和已校验内容可以进入对局事件流。
- SSE 使用递增事件编号；断线重连后，前端通过事件编号和当前状态快照恢复遗漏状态。
- 首版 Fastify 服务只监听本机地址 `127.0.0.1`，不开放局域网访问。
- 首版不实现登录、账户和多用户系统。
- API 密钥只从服务端环境变量读取，不得发送至浏览器、写入数据库或输出到日志。
- 默认测试不依赖 API 密钥，使用可控假模型和临时 SQLite 覆盖状态机、信息隔离、模型适配器、API 与完整对局流程。
- 提供显式真实模型验收命令 `pnpm test:live`，调用 DeepSeek、豆包、千问和复盘模型验证真实描述、信念、投票、信息边界与异步复盘。
- 真实模型验收不得成为默认测试或普通开发启动的隐式步骤，避免意外产生费用。
- 真实模型验收成功后生成脱敏 Markdown 报告和关键截图，保存到仓库作为验收证据。
- 报告记录验收时间、模型标识、信息隔离断言、结构校验、调用耗时、重试次数和异步复盘结果。
- 报告与截图不得包含 API 密钥、敏感中转地址、完整请求头、被拦截的违规原文或无必要的完整模型响应。
- 角色素材制作前先完成漫画分镜线框和统一素材规范。
- 首次只生成一个模型角色的默认状态样稿；角色比例、线条、颜色和手绘程度经项目负责人确认后，才能批量生成其余角色与状态。
- 批量素材统一处理透明背景、尺寸、安全裁切区域、文件命名和 WebP 压缩。
- 统一视觉风格为略有手绘抖动的墨线、克制的平涂色块和轻微纸张纹理，不使用复杂厚涂光影。
- 角色在小尺寸和移动端裁切后仍须保持清晰轮廓与状态辨识度。
- 模型角色不直接使用网上原图，由项目负责人使用统一提示词模板生成 DeepSeek、豆包、千问的项目专用女性拟人角色图。
- 角色可以提炼网络主流形象的通用视觉意象，但不得复刻某一张具体二创作品、官方数字人的具体脸部或未经许可的 Logo。
- 首次只生成 DeepSeek 默认状态样稿；画风确认后，以已确认角色图作为参考派生其他状态，保证脸部、发型、服装和配色一致。
- 最终素材应保留生成工具、日期、提示词和必要的后期处理记录，便于说明来源。
