# 首个纵向里程碑规格

- 状态：待开发
- 目标：使用可控假模型跑通可持久化、可恢复的基础玩法完整对局

## 1. 成果定义

本里程碑结束时，项目应是一个可以在本机启动并通过浏览器完整游玩的全栈应用，而不是只有工程骨架或某一层演示。

玩家能够配置新对局、查看自己的词牌、开始游戏、与三名假模型 AI 依次描述和秘密投票、经历平票辩解与重投、淘汰、观战或放弃，并看到正确终局。页面刷新和 SSE 重连不得丢失或重复已确认动作。

## 2. 范围

### 2.1 必须包含

- pnpm workspace、React/Vite/TypeScript Web、Fastify/TypeScript Server、共享 TypeScript/Zod 包。
- SQLite/Drizzle 迁移、不可变事件、当前快照、命令幂等和安全 SSE 帧。
- 固定一名人类、DeepSeek/豆包/千问三个显示角色、一名卧底。
- 仓库 JSON 词库的已审核子集、难度筛选、随机词组与卧底分配。
- 准备、描述、普通秘密投票、统一揭晓、淘汰和两种正常胜负。
- 一次平票辩解、非候选秘密重投、再次平票与全员最高票分支。
- 人类主动放弃、人类淘汰后选择观战或放弃。
- 可控假模型、信息隔离、刷新恢复、SSE 重连和端到端测试。
- 风格化线框、响应式漫画分镜、词牌翻面、操作反馈、已索引 AI 角色状态素材和终局分层揭晓。

### 2.2 明确不包含

- 真实模型调用和 `pnpm test:live` 的有效实现。
- 异步 AI 复盘任务与 AI 总结。
- 首次泄词后再次泄词的强制退出完整流程。
- 最终 30 组词库交付；本阶段只使用人工审核子集。
- 人类剪影、词牌、场景和通用 UI 的最终精细素材，以及完整纸张纹理和高级动画；三个 AI 角色的已有状态素材可按索引直接接入。
- 猜词玩法、可选人数、多卧底、模型阵容选择、账户或局域网访问。

延后能力不得以硬编码假响应或不可用控件伪装完成。架构只保留清晰扩展边界。

## 3. 实施切片

每个切片完成后都必须形成可运行或可测试的纵向增量；不能先一次性搭完所有后端再补 UI。

### 切片 1：工程基线与共享契约

**实现**

- 初始化 pnpm workspace、根脚本和 TypeScript 配置。
- 创建 `apps/web`、`apps/server`、`packages/shared`、`data` 和 `tests/e2e`。
- 在共享包定义对局配置、状态、阶段、命令、事件、视图和错误 Schema。
- 建立基础 CI 可执行命令，但不创建真实模型调用。

**验收**

- Web 与 Server 可由单一 `pnpm dev` 启动。
- `build`、`typecheck`、`lint` 和最小单元测试通过。
- 共享包不依赖 React、Fastify、Drizzle 或网络。

**依赖规格**：[`../spec/architecture.md`](../spec/architecture.md)、[`../spec/game-domain.md`](../spec/game-domain.md)。

### 切片 2：创建、准备与持久化词牌

**实现**

- 建立词库子集 JSON、集合校验和 SQLite 同步。
- 创建数据库迁移、对局/玩家/事件/快照/命令表。
- 实现固定阵容创建、难度筛选、随机词组、随机卧底和首轮顺序。
- 实现新对局表单、未完成对局检查、准备页、词牌本地翻面和 `StartGame`。

**验收**

- 固定种子可复现四个任意卧底座位。
- 创建后刷新保持相同词组和分配，仍等待玩家开始。
- 浏览器只收到人类自己的词牌，翻面不产生 API 或领域事件。
- 存在未完成对局时不能直接创建第二局。

**依赖规格**：[`../spec/persistence.md`](../spec/persistence.md)、[`../spec/api-and-events.md`](../spec/api-and-events.md)、[`../spec/frontend-ux.md`](../spec/frontend-ux.md)。

### 切片 3：正常描述与投票闭环

**实现**

- 实现纯状态机的描述顺序、行动轮换、投票、淘汰和胜负。
- 实现内容校验器和可控 `FakeAgentPolicy`。
- 实现 Agent 输入投影、私有信念快照和自动推进。
- 实现 REST 描述/投票、SSE 安全帧、漫画分镜和统一投票揭晓。

**验收**

- 人类轮次暂停等待，AI 轮次自动连续推进。
- 投票进度和统一揭晓之间无目标泄漏。
- 一局可到达平民胜利；另一固定剧本可到达卧底胜利。
- 假模型收到的输入通过信息隔离负向断言。

**依赖规格**：[`../spec/agent-runtime.md`](../spec/agent-runtime.md)、[`TESTING.md`](TESTING.md)。

### 切片 4：平票分支

**实现**

- 实现部分平票候选辩解、非候选重投和重投结果。
- 实现再次平票无人淘汰和下一轮起始位置轮换。
- 实现全员最高票直接无人淘汰。
- 补齐对应分镜、合法操作投影和假模型剧本。

**验收**

- 候选不参与重投，重投目标只能是候选。
- 辩解成为后续参与重投 Agent 的公开输入。
- 再次平票和全员平票均不产生淘汰。
- 事件序列可准确复盘分支原因。

**依赖规格**：[`../spec/game-domain.md`](../spec/game-domain.md) 第 6–7 节。

### 切片 5：事务、幂等与恢复

**实现**

- 将事件、私有动作、公开帧和快照纳入同一事务。
- 实现 `commandId`、`expectedRevision`、稳定 `actionId` 和行动锁。
- 实现 SSE `Last-Event-ID` 补发、状态同步和客户端去重。
- 服务启动时恢复轮到 AI 的对局，轮到人类时保持等待。

**验收**

- 故障注入证明任一持久化步骤失败都整体回滚。
- 双击、刷新、重连和重复调度不产生重复事件或动作。
- AI 调用期间状态被放弃时，旧结果不能提交。
- 在准备、发言、投票和等待观战节点刷新均可正确恢复。

**依赖规格**：[`../spec/persistence.md`](../spec/persistence.md) 第 3–7 节、[`../spec/api-and-events.md`](../spec/api-and-events.md) 第 5 节。

### 切片 6：放弃、淘汰观战与终局展示

**实现**

- 人类存活时二次确认放弃。
- 人类淘汰后暂停，选择继续观战或放弃。
- 观战后 AI 自动推进，公开投影不升级为上帝视角。
- 实现正常终局胜负、自动依次揭晓和确定性事实入口。
- 实现已放弃终局的不完整记录，不生成阵营胜者。

**验收**

- 两个放弃入口均保留截至当时的事实且无 `winnerCamp`。
- 观战者看不到任何新增私有字段，也不再拥有行动控件。
- 正常终局事实先于动画持久化，刷新不重复创建终局。
- 减少动态效果模式可以完成揭晓。

**依赖规格**：[`../spec/frontend-ux.md`](../spec/frontend-ux.md) 第 4.7–4.10 节。

### 切片 7：完整验证与文档收口

**实现**

- 完成领域、内容、数据库、API/SSE、组件和 Playwright 测试。
- 在桌面与移动视口使用实际应用完成黄金路径和关键边界验证。
- 更新根 README 的安装、环境、启动、默认测试、架构、信息隔离和已知问题。
- 更新项目开发记录，说明实现、验证结果和延后内容。

**验收**

- [`TESTING.md`](TESTING.md) 的首个里程碑清单全部满足。
- 所有默认命令不读取密钥、不访问真实模型。
- 浏览器控制台、服务日志和网络请求没有意外错误或私有字段。
- 代表性截图确认桌面、移动端、平票、观战和终局布局。

## 4. 完成定义

只有同时满足以下条件，里程碑才算完成：

1. 浏览器可以从新对局到正常终局完成真实前后端链路。
2. 正常、平票、恢复、放弃和淘汰观战端到端场景均通过。
3. 信息隔离负向矩阵在 Agent 输入、REST、SSE、日志和 DOM 层通过。
4. 事件、快照和安全流帧经过事务与幂等测试。
5. 桌面和移动端实际使用验证完成，无阻塞性布局或控制台错误。
6. `build`、`typecheck`、`lint`、默认测试和 E2E 全部通过。
7. README 和项目开发记录反映实际状态与已知限制。

完成定义不要求真实模型、异步 AI 复盘、最终素材或 30 组完整词库。

## 5. 开发门禁

以下情况必须暂停当前切片并回到负责人确认：

- 需要改变已确认游戏规则、信息公开范围或首个里程碑范围。
- 需要更换 React/Vite/Fastify/SQLite/Drizzle/pnpm 核心技术栈。
- 需要真实付费模型调用、删除本地用户数据或执行不可逆迁移。
- 准备 Git 提交、推送或正式发布。

目录名、字段名、路由名、CSS 组织和测试文件组织等不改变产品行为的工程细节采用合理默认值，不逐项确认。
