- 日期：2026-08-14
- 状态：已确认
- 决策：仅较大的功能、架构或正式发布变更使用版本号；小变更只进入开发记录。
- 原因：避免版本号被细碎调整稀释，同时保留完整开发轨迹。

## DEC-003 首版技术框架

- 日期：2026-08-14
- 状态：已被 DEC-048 替代
- 推荐方案：Next.js、React、TypeScript、Tailwind CSS、SQLite、Drizzle ORM、OpenAI 官方 JavaScript SDK，以及服务端权威游戏状态机。
- Agent 方案：不采用自治 Agent 群聊；由统一编排器为每名 AI 构建隔离上下文，并要求模型以结构化数据返回描述或投票。
- 原因：单仓库即可覆盖界面、服务端接口和本地数据，便于交付；显式编排比自治 Agent 更容易证明信息隔离、复现流程并进行自动化测试。
- 备选方案：Python FastAPI 后端配 React 前端；仅在需要突出 Python Agent 生态或复杂离线评测时采用。

## DEC-004 AI 玩家认知架构

- 日期：2026-08-14
- 状态：已确认，后续细节由 DEC-015、DEC-034、DEC-035 和 DEC-038 补充
- 推荐方案：每名 AI 使用独立的私有信念状态，按“观察公开事件、更新猜测、决定行动、记录依据”的循环运行。
- 私有信念：自己的阵营猜测、多个敌对阵营身份词候选、各玩家的可疑度、判断理由和置信度。
- 词语边界：AI 已知自己的词，不重复猜测自己的身份词；敌对阵营身份词在身份揭晓前不强行标注为平民词或卧底词。
- 对局行为：描述和投票读取该 AI 自己的信念状态，但不能读取其他 AI 的信念、词语或真实阵营。
- 复盘方式：对局结束后按时间线展示各 AI 的信念变化、关键证据和最终判断。
- 原因：在保持服务端确定性流程的同时，形成真实的多主体认知差异，并提供可解释的复盘材料。

## DEC-005 Multi-Agent 协作边界

- 日期：2026-08-14
- 状态：已确认，后续细节由 DEC-029、DEC-030、DEC-031 和 DEC-032 补充
- 推荐方案：玩家 Agent 之间只通过游戏允许的公开描述和投票间接影响彼此，不直接共享私有记忆或内部推理。
- 可选扩展：增加不参与游戏的复盘分析 Agent，在对局结束后读取完整事件和已解密的私有轨迹，生成全局复盘。
- 暂不采用：对局中自由私聊、共享草稿或由主管 Agent 指挥玩家；这些方式会破坏桌游的信息边界。

## DEC-006 视觉素材策略

- 日期：2026-08-14
- 状态：已确认，后续细节由 DEC-041、DEC-043、DEC-055、DEC-056 和 DEC-058 补充
- 推荐方案：先用项目自有的轻量 2D 素材规范完成界面骨架，再按统一角色设定补充 AI 生成的透明背景角色素材。
- 原因：通用免费素材很难同时满足手绘风格、角色一致性和清晰授权；自有素材规范更利于后续替换和控制仓库体积。

## DEC-007 身份信息与淘汰公开范围

- 日期：2026-08-14
- 状态：已确认
- 决策：玩家开局只获得自己的词牌，不获得真实阵营；淘汰后只公开被淘汰的玩家，不公开其阵营和词牌。
- 信息边界：存活玩家只能使用自己的词牌、公开描述、公开投票和淘汰名单进行判断。
- 原因：持续保留阵营判断的不确定性，使 AI 的私有信念更新和赛后复盘具有实际意义。

## DEC-008 胜负规则与猜词玩法顺序

- 日期：2026-08-14
- 状态：已确认
- 基础玩法：卧底被淘汰时平民获胜；场上只剩两人且卧底仍存活时卧底获胜。
- 后续玩法：基础玩法完成并验收后，再增加卧底和平民均可参与的敌对阵营词猜测机制。
- 版本策略：猜词玩法属于较大功能，但只在开始实际实现时分配版本号。
- 原因：先用明确、可测试的胜负规则交付完整闭环，再单独验证猜词机制对平衡性和流程的影响。

## DEC-009 发言顺序

- 日期：2026-08-14
- 状态：已确认
- 决策：首轮随机确定发言顺序；后续保持座位相对顺序，每轮将起始玩家向后轮换一位；淘汰玩家自动跳过。
- 原因：降低固定后手带来的信息优势，同时保持顺序清晰、可预测和易于测试。

## DEC-010 投票信息与复盘快照

- 日期：2026-08-14
- 状态：已确认
- 决策：所有存活玩家独立秘密投票；前端按角色逐个展示“正在投票”和“已完成投票”的非信息性状态，具体选择保持隐藏，全部完成后统一公开结果。
- Agent 记录：每名 AI 在提交投票时冻结当前信念分布、目标玩家和投票理由；后续信念更新不得覆盖该快照。
- 信息边界：AI 作出选择时不能看到本轮其他玩家尚未公开的投票；逐个展示仅是交互节奏，不改变秘密投票规则。
- 原因：消除投票次序优势，并保证复盘能够还原 AI 在当时信息条件下的真实判断。

## DEC-011 平票处理

- 日期：2026-08-14
- 状态：已确认
- 决策：最高票平票后，平票候选依次进行一次简短辩解；辩解完成后，由未进入平票的其他存活玩家针对平票候选重新秘密投票；平票候选不参与重投；再次平票则本轮无人淘汰。
- Agent 行为：辩解作为新的公开事件进入所有存活 AI 的上下文，参与重投的 AI 在投票前更新自己的私有信念。
- 原因：为重新投票提供新增信息，并保留对辩解如何改变判断的复盘价值。

## DEC-012 描述限制与原词防泄露

- 日期：2026-08-14
- 状态：已确认
- 决策：公开描述限制为 2 至 40 个字符、最多两句，禁止出现自己的词牌原词。
- 表达质量：AI 提示词要求避免机械复读已有公开内容，但服务端不对玩家之间、轮次之间或描述与辩解之间的相同文本执行重复拦截。
- 双重校验：提示词要求模型生成前自检；服务端对模型结果执行独立的确定性校验，不能只信任模型声明。
- 违规处理：校验失败的描述不公开、不写入公共事件，也不触发其他 Agent 更新；模型必须重新组织发言。
- 原因：降低直接泄露词牌的风险，同时保留足够的自然表达空间。

## DEC-013 重复泄露原词的处罚

- 日期：2026-08-14
- 状态：已确认
- 决策：AI 或人类玩家首次泄露自己的词牌原词时，该描述作废并获得一次重新发言机会；再次泄露时公开报告“该玩家违反游戏规则”，强制退出对局并立即执行胜负判断。
- 校验边界：人类输入在前端提供即时提示，但最终以服务端校验为准；AI 和人类共用相同的核心校验函数。
- 信息边界：首次违规内容不进入公共上下文；第二次违规只公开违规结论，不公开包含原词的原始内容。
- 原因：确保规则对人类和 AI 一致，同时避免泄露内容污染后续 Agent 判断。

## DEC-014 游戏违规与系统错误边界

- 日期：2026-08-14
- 状态：已确认
- 游戏违规：仅指玩家在描述中直接泄露自己的词牌原词；连续两次发生时执行强制退出处罚。
- 格式错误：长度或句数不合规则；人类继续修改，AI 进入格式纠正流程。公开内容与历史文本相同不属于格式错误。
- 系统错误：模型接口超时、限流、网络异常或无效结构化输出；暂停并恢复当前动作，不处罚玩家，也不改变胜负。
- 原因：胜负只能受到游戏行为影响，不能由模型服务或格式控制的不稳定性决定。

## DEC-015 Agent 信念更新时机

- 日期：2026-08-14
- 状态：已确认
- 决策：AI 在自己的行动节点更新信念，包括发言前、投票前、平票辩解前和重新投票前；不在每条公开信息出现后立即单独调用模型。
- 调用方式：信念更新与当前行动尽量合并为一次结构化模型调用，信念结果冻结为该动作发生时的历史快照。
- 原因：保留可解释的 Agent 行动依据，同时控制模型调用次数、等待时间和费用。

## DEC-016 首版人数与扩展边界

- 日期：2026-08-14
- 状态：已确认
- 首版配置：一名人类、三名 AI、一名卧底和三名平民。
- 扩展设计：创建对局的校验层固定四人；核心游戏引擎使用玩家集合和配置对象，不依赖固定座位字段或写死的四人循环。
- 暂不实现：人数选择界面、多卧底比例和对应的新胜负条件。
- 原因：先完成最小可玩闭环，同时避免未来扩展人数时重写核心领域模型。

## DEC-017 模型角色化 Agent

- 日期：2026-08-14
- 状态：已确认
- 决策：不同厂商或不同模型可以作为独立 Agent 的角色身份；每个角色预设少量显示信息、表达倾向和基础提示词。
- 模型边界：所有角色共用同一中转站连接与统一模型适配器，只通过角色配置中的模型 ID 选择不同模型；游戏引擎不感知厂商和具体型号。
- 扩展方式：首版提供三个模型角色配置，未来通过增加配置扩展人数，不为每个角色编写独立 Agent 类。
- 安全要求：中转接口地址和密钥只从环境变量读取，不进入代码、仓库、公开日志或复盘记录。
- 原因：让 Multi-Agent 的模型差异成为可感知的产品特征，同时保持人数、角色和模型供应方可替换。

## DEC-018 模型角色展示方式

- 日期：2026-08-14
- 状态：已确认，对局外"不选择 model"的部分由 DEC-085 替代
- 对局内：直接使用真实模型简称作为玩家名，例如 `DeepSeek`；不显示额外模型标签。
- 对局外：使用独立身份卡展示模型名称、三个性格标签和该模型的提示词。
- 提示词分层：人格提示词负责角色风格；系统提示词负责游戏规则、私有信息边界和结构化输出，两者独立维护。
- 原因：保持对局界面简洁，同时在对局外提供足够的模型身份和 Agent 设计信息。

## DEC-019 身份卡提示词公开范围

- 日期：2026-08-14
- 状态：已确认
- 身份卡：展示简短且完整的人格提示词，说明模型角色的表达风格和判断倾向。
- 系统提示词：负责游戏规则、信息隔离、结构化输出、原词校验和错误恢复，不在身份卡展示。
- 可审查性：系统提示词模板保存在代码和开发文档中，供开发验收；运行时私有数据和密钥不得写入模板或文档。
- 原因：身份卡保持简洁可读，同时不牺牲系统设计的透明度和可验证性。

## DEC-020 首版模型阵容与二期选择功能

- 日期：2026-08-14
- 状态：已确认，其中"首版不开发单座位 model 选择界面"的部分由 DEC-085 替代
- 首版阵容：固定三个 AI 模型身份，分别为 `DeepSeek`、`豆包`、`千问`。
- 首版范围：不开发模型选择和角色数量选择界面；三个身份的实际模型 ID 通过本地模型连接配置绑定。
- 二期目标：玩家选择参与对局的角色数量，并为每个 AI 座位选择具体模型；同时允许扩展新的模型身份。
- 架构要求：首版界面固定阵容，但核心引擎和 Agent 配置继续使用动态集合，不将三个模型名称写入游戏规则。
- 原因：先形成清晰、稳定的多模型首发阵容，再将可配置竞技场作为后续较大功能开发。

## DEC-021 模型角色人格强度

- 日期：2026-08-14
- 状态：已确认
- 决策：采用轻人格。DeepSeek、豆包、千问共享相同的游戏规则、信息边界、推理任务和输出结构，只分别附加简短的表达倾向提示。
- 约束：人格提示不得改变模型可见信息、推理字段、投票义务或校验标准。
- 目的：为身份卡和对局表现提供适度差异，同时尽量保留不同模型在相同任务下的自然行为差异。

## DEC-022 首版词语来源

- 日期：2026-08-14
- 状态：已确认
- 决策：首版使用项目内置、经过人工筛选的词语对，由服务端在开局时随机抽取。
- 元数据：词语对包含分类、难度和启用状态，为后续筛选及扩展保留空间。
- 暂不采用：模型动态生成词语对，以及由唯一人类玩家输入本局词语对。
- 原因：保证词语质量、对局公平、测试可复现，并避免人类玩家提前获知双方词语。

## DEC-023 词语阵营归属与难度

- 日期：2026-08-14
- 状态：已确认
- 阵营归属：每组词语对固定标注平民词和卧底词，抽取后不随机交换。
- 难度分级：词库提供简单、困难两档；简单词具有较多直观描述角度，困难词具有较少安全描述角度或需要更细致的表达。
- 信息边界：运行时模型不能读取完整词库及阵营映射，只能看到自己的词牌，因此固定映射不会向 Agent 提供额外经验信息。
- 原因：固定映射有利于人工控制双方难度；较大词库也能降低重复抽取对游戏体验的影响。

## DEC-024 难度选择方式

- 日期：2026-08-14
- 状态：已确认
- 决策：由人类玩家在开局前选择简单或困难难度，服务端从对应难度的启用词语对中随机抽取。
- 记录：难度作为不可变的对局配置写入事件和复盘，便于按难度验收与分析。
- 原因：玩家可以主动控制体验，并能稳定复现和验证不同难度的词库表现。

## DEC-025 第一轮投票时机

- 日期：2026-08-14
- 状态：已确认
- 决策：第一轮所有玩家完成一次描述后立即进入秘密投票，不设置第一轮免投票规则。
- 复盘：保留第一轮行动前信念和投票快照，用于分析 Agent 在信息较少时的判断与置信度。
- 原因：保持对局节奏紧凑，并让首轮推理成为可观察、可比较的 Agent 行为。

## DEC-026 最大回合数

- 日期：2026-08-14
- 状态：已确认
- 决策：正式对局不设置最大回合数，只要尚未满足胜负条件就继续进行。
- 排除规则：不因达到轮数上限判定平局，也不通过随机淘汰强制结束。
- 测试边界：自动化测试可设置独立的执行次数保护，避免测试程序无限运行；该保护不进入正式游戏状态机。

## DEC-027 主动放弃对局

- 日期：2026-08-14
- 状态：已确认
- 决策：人类玩家可以在二次确认后主动放弃对局。
- 结果：对局标记为“已放弃”，不判定平民或卧底胜利，也不把人类玩家视为游戏内淘汰。
- 记录：保留放弃前的公开事件、AI 信念快照、投票和错误记录，生成明确标注为不完整的复盘。
- 原因：为长期平票、模型服务异常或用户主动结束提供退出路径，同时不污染阵营胜负数据。

## DEC-028 未完成对局恢复

- 日期：2026-08-14
- 状态：已确认
- 保存方式：合法描述、信念快照、投票、淘汰、回合切换和终局等已完成事件自动持久化。
- 重新进入：检测到未完成对局时，由人类玩家选择“继续对局”或“放弃并开始新对局”。
- 放弃处理：旧对局标记为已放弃，不产生阵营胜负，并保留不完整复盘。
- 原因：兼顾本地运行稳健性和用户选择权，避免刷新或模型故障导致进度丢失。

## DEC-029 赛后复盘架构

- 日期：2026-08-14
- 状态：已确认
- 基础复盘：程序根据持久化事件生成确定性事实时间线，展示身份、词牌、描述、辩解、投票、淘汰和信念快照。
- AI 复盘：独立复盘 Agent 在终局后读取完整对局记录，分析关键转折、判断得失、重要描述和模型表现。
- 展示边界：AI 总结与事实数据明确分区，不能覆盖或修改原始事件；总结失败不影响基础复盘可用性。
- 原因：同时保证事实可验证性和复盘的可读性、分析价值。

## DEC-030 复盘 Agent 模型配置

- 日期：2026-08-14
- 状态：已确认
- 决策：复盘 Agent 使用独立模型 ID、独立上下文和独立提示词，但复用所有参赛 Agent 的统一中转站连接与认证配置。
- 模型来源：模型 ID 可以指向 DeepSeek、豆包或千问，也可以配置第四个模型；游戏引擎不依赖具体选择。
- 可替换性：复盘模型可单独更换，不影响参赛角色和历史对局；复盘记录标注实际模型标识。
- 安全边界：不在复盘中保存 API 密钥或敏感中转地址。

## DEC-031 异步复盘执行

- 日期：2026-08-14
- 状态：已确认
- 决策：终局后自动创建异步复盘任务；保存胜负与事实时间线后立即结束当前请求，不等待模型总结。
- 非阻塞要求：玩家可以立即返回大厅或开始新对局，复盘任务不得锁定当前用户或游戏创建流程。
- 持久化要求：任务状态写入 SQLite，服务重启后可以恢复待处理任务，不使用纯内存任务作为唯一执行依据。
- 失败处理：事实复盘始终可用；AI 总结显示生成中、已完成或失败状态，失败后允许重新生成。

## DEC-032 模型调用调度优先级

- 日期：2026-08-14
- 状态：已确认
- 决策：实时对局调用拥有高于后台复盘的调度优先级。
- 调度规则：已发出的复盘请求正常完成；尚未开始的复盘任务等待实时对局调用；后台最多同时运行一个复盘任务。
- 持久化：任务状态和优先级写入数据库，重启恢复后继续遵守相同规则。
- 原因：避免浪费已经产生费用的请求，同时优先保证描述、投票和辩解的交互响应。

## DEC-033 中转接口协议

- 日期：2026-08-14
- 状态：已确认
- 决策：首版只支持一个 OpenAI 兼容中转站，DeepSeek、豆包、千问和复盘模型只通过不同模型 ID 配置。
- 共用能力：统一模型客户端、基础地址和认证负责请求、超时、错误映射、调用日志和响应解析。
- 首版边界：不开发厂商原生接口和原生 SDK 适配器。
- 原因：减少多模型接入的重复实现，并让新增或替换模型主要通过配置完成。

## DEC-034 模型结构化输出

- 日期：2026-08-14
- 状态：已确认
- 决策：提示词要求模型返回约定 JSON，服务端使用 Zod 对字段、类型、枚举和数值范围执行最终校验。
- 修复流程：首次结构错误时执行一次只针对格式的修复请求；再次失败则记录系统错误并允许重新执行当前动作。

## DEC-051 前后端实时通信

- 日期：2026-08-15
- 状态：已确认

- 事件通道：AI 思考状态与已确认的公开对局事件使用 SSE 单向推送。

## DEC-068 原词泄露确定性判定

- 原因：阻止常见的空格和标点绕过，同时避免模糊语义误判直接改变胜负。

## DEC-069 人类淘汰后的对局处理

## DEC-072 模型调用失败重试与终止

- 日期：2026-08-16
- 状态：已确认
- 决策：模型调用进入系统错误后，对当前行动最多自动重试三次；连同初始调用，同一行动最多执行四次有效调用尝试。
- 用户提示：从第一次开始重试时立即显示脱敏错误类型、当前重试次数和总次数，不等全部失败后才提示。
- 重试间隔：三次重试前均固定等待 2 秒；自动化测试使用可注入时钟，不实际等待。
- 结构错误衔接：首次结构化输出错误先执行既定的一次格式修复；修复仍失败后进入上述系统错误重试流程。
- 终止结果：三次自动重试后仍失败，对局自动标记为“系统异常终止”，不判平民或卧底胜利，也不记为玩家主动放弃。
- 恢复边界：“系统异常终止”是不可恢复终局，不允许重新打开原事件流或从失败行动继续；历史页只提供错误摘要、不完整复盘和开始新对局入口。
- 记录要求：保存每次尝试的错误分类、时间、耗时和脱敏结果，保留截至故障前的事件与不完整事实复盘；不保存密钥、敏感地址或无必要的完整原始响应。
- 稳健性要求：重试沿用当前行动的幂等标识，失败尝试不得生成公开行动事件或重复状态转换。
- 原因：允许中转服务从短暂故障中自动恢复，同时为持续故障设置明确成本和等待上限，并准确区分系统故障、玩家放弃与正常胜负。

## DEC-079 终局分阶段揭晓

- 日期：2026-08-16
- 状态：已确认
- 决策：终局按“结果公布、身份与词牌揭晓、确定性事实复盘、异步 AI 总结”四个层次展示。
- 结果公布：正常终局显示平民或卧底胜利；主动放弃和系统异常终止只显示对应状态，不伪造阵营胜负。
- 身份揭晓：结果公布后按座位顺序翻开全部玩家的真实阵营和词牌，并明确标识卧底。
- 事实复盘：身份揭晓完成后立即开放程序生成的确定性时间线、行动、投票、淘汰、错误和 AI 私有信念快照。
- AI 总结：独立区域异步显示生成中、已完成或失败；总结不能修改事实，也不阻塞事实查看或新对局创建。
- 原因：先建立确定的胜负与身份事实，再逐步进入可审计的推理过程，兼顾终局仪式感、复盘清晰度和异步任务可靠性。

## DEC-086 Agent 错误自动恢复优先

- 日期：2026-08-17
- 状态：已确认
- 决策：Agent 行动按“自动恢复优先、耗尽后才提示玩家”处理；发言、辩解、投票和重投共用分类与预算，不把所有失败压成一个通用错误。
- 错误分类：区分超时、网络、限流、服务异常、认证/配置、模型不存在、空响应、非法 JSON、Schema/信念错误、非法行动、发言格式、原词泄露、过期结果、持久化和内部错误。
- 结构恢复：模型字段缺失、类型错误、未知字段、非法信念或投票目标时只允许一次格式修复；仅首尾空白、JSON 包裹和概率浮点残差允许安全规范化，不得用默认发言、默认理由或伪造信念掩盖错误。
- 内容恢复：长度或句数错误秘密作废并重新生成；首次原词泄露秘密拦截并重新生成，第二次公开规则违规、强制该玩家退出并立即判断胜负。失败原文不进入事件、日志、复盘或后续 Agent 输入。
- 系统恢复：超时、网络、429、5xx 和空响应按既有上限自动重试；401/403、模型不存在和缺少模型配置属于永久错误，不盲目重复调用。自动恢复过程中只展示非信息性工作/重试状态，耗尽后才显示脱敏终止摘要。本条替代 DEC-072“首次重试即向玩家显示错误类别”的提示时机，其三次重试上限、固定等待和不可恢复终止边界保持不变。
- 并发与持久化：模型返回后必须重新核对 `baseRevision`；结果过期则丢弃。通过校验的输出在事务失败时只能重试提交，不得再次调用模型或产生不同动作。
- 原因：优先保证对局连续性，避免永久错误的无效等待、重复付费和失败内容泄漏，同时让最终错误仍可定位和审计。

## DEC-090 通用中转站按精确 model ID 配置请求参数

- 日期：2026-08-18
- 状态：已确认并实现
- 决策：不提供基于 model 名称或模型家族的通用 `auto`。新增服务端变量 `OPENAI_COMPATIBLE_MODEL_EXTRA_BODY`，其 JSON 结构为“精确 model ID → 请求参数对象”。

- 安全：映射只保留在服务端进程内，不下发浏览器、不落库、不写日志或复盘。它不包含 Base URL、API Key 或请求头。
- 原因：OpenAI 兼容协议没有统一的关闭思考字段；精确映射比按名称猜测更可控，也能让不同模型和评测模型分别使用各自中转站实际支持的参数。

## DEC-092 服务中断后的对局恢复边界

- 日期：2026-08-19
- 状态：已确认，已实现
- 故障归属：后端进程、操作系统或正常停机导致正在执行的模型请求中断，属于运行环境中断，不归责于模型内容生成，也不消耗 DEC-072/086 的常规模型重试预算。
- 中断状态：保留对局顶层 `in_progress`，另以持久化运行状态表示“中断后等待玩家确认”；服务恢复后不得自动继续或直接终止旧局。
- 玩家选择：玩家重新进入时选择继续上一局，或开始新对局。继续时重新执行被中断动作的一次独立恢复调用，之后原有模型重试预算仍完整保留；开始新局时，旧局以无胜者的“中断后未继续”原因终止，区别于玩家主动放弃、模型失败和正常胜负。
- 正常停机：停止接收新命令，立即持久化受影响动作的中断状态，取消本进程对模型 HTTP 响应的等待并关闭服务；不额外等待后台调用自然结束。
- 复盘边界：被中断的后台复盘在服务恢复后自动进入待处理队列，不要求玩家确认，也不影响确定性事实复盘。
- 原因：把模型质量、用户选择和运行环境故障分开归因，既避免误耗模型重试预算，也避免服务重启后擅自替玩家继续付费调用。

## DEC-093 实时对局与异步复盘调度边界

- 日期：2026-08-19
- 状态：已确认，已实现
- 全局并发：后台 AI 复盘全局最多同时执行一个；实时投票仍可并行调用三个参赛 Agent。若一项复盘已经发出，允许它与新对局的实时调用并行完成，因此峰值为三个投票调用加一个已发出复盘调用。
- 启动门禁：存在 `preparing`、`in_progress` 或 `awaiting_spectator` 对局时，不启动新的复盘模型请求；已经发出的复盘不取消，尚未发出的持久化任务继续等待。
- 空闲优先级：进入空闲后，优先生成刚结束对局的复盘，再按创建时间处理更早的待处理复盘；任务状态和顺序必须可在服务重启后恢复。
- 事实边界：复盘失败、等待或恢复不修改游戏事件、胜负和确定性事实时间线，也不阻止玩家开始新局。
- 原因：优先保证玩家正在进行的实时对局，同时不浪费已产生费用的复盘请求，并用单并发限制后台成本。

## DEC-094 单人本地应用的轻量可靠性

- 日期：2026-08-19
- 状态：已实现
- SQLite 一致性：检测到数据库完整性异常时停止游戏、模型、复盘、导出和写入，只在 `127.0.0.1` 保留可返回脱敏状态的健康检查；保留数据库及 WAL 原文件，不自动猜测修复。
- SQLite 繁忙：使用可配置的短时有限等待，默认约 3 秒；耗尽后返回脱敏“本地数据繁忙”。只允许重试事务，绝不能因此重新调用模型。
- 备份范围：只在执行数据库迁移前生成可恢复备份，不增加每局备份或每日轮转备份。
- SSE 恢复：连接中断约 3 秒后显示非阻塞恢复提示，保留当前画面和输入；客户端持续采用递增间隔重连并提供“立即重试”，恢复后重新获取权威视图和游标，不自动整页刷新。
- 人类命令恢复：当前标签页以 `sessionStorage` 保存待确认命令及稳定 `commandId`。响应丢失时先读取权威状态；已经提交则更新界面，尚未提交才使用相同 ID 和相同负载重试。修订冲突只刷新状态，不归类为模型错误。
- 范围控制：首版不建设多节点、账户级容灾、持续备份或企业级灾难恢复。
- 原因：覆盖本地单人应用最可能发生的数据占用、断线与响应丢失问题，同时避免超出产品规模的可靠性工程。

## DEC-095 Agent 调用与上下文审计

- 日期：2026-08-19
- 状态：已确认，已实现
- 调用台账：实现持久化 `model_attempts`，长期保存角色、model ID、动作类型、尝试序号、开始/结束时间、耗时、结果分类，以及是否发生格式修复或内容重生成等脱敏元数据。
- 禁止落库：`model_attempts` 不保存完整 Prompt、词牌、私有信念正文、模型原始响应、API Key、Base URL 或请求头。
- 上下文审计：通过独立于业务数据库和普通日志的本地审计文件记录上下文清单，包括允许范围、实际片段来源和可见级别、公开事件游标、模板版本、最终 Prompt 哈希及边界校验结果。完整 Prompt 和原始响应默认关闭，只能在显式验收/调试模式开启，并继续过滤连接凭据和请求头；审计目录不得进入 Git。
- 保留策略：`model_attempts` 与结构化上下文清单随对局长期保留，删除对局时一起清理；完整 Prompt/原始响应调试记录最多保留 7 天并受本地容量上限约束，超限时从最旧记录开始清理。服务启动时执行轻量清理，并允许玩家主动清除完整调试记录；清理完整记录不得误删长期脱敏元数据和结构化清单。
- 调用前门禁：Harness 在请求发出前校验目标 Agent 是否获得其他玩家词牌、其他 Agent 私有信念、未公开选票或未来事件；发现越权时阻止模型调用并记录 `context_boundary_violation`。
- 统一链路：浏览器命令、服务端动作和模型尝试使用 `gameId -> commandId -> actionId -> attemptId` 关联；并行投票的每名 Agent 使用独立动作和尝试 ID，但仍归属于同一玩家命令。
- 开发者门禁：服务端环境变量 `AGENT_DEVELOPER_MODE=true` 是权威总开关，默认关闭。关闭时不注册诊断 API、不返回诊断数据，前端也不显示开发者入口；开启后，设置区才显示仅保存在当前标签页的“开发者模式”开关。
- 调试面板：前端开发者模式打开后提供只读 Agent 观测面板，按“调用链、上下文、错误与恢复、复盘调度”展示脱敏信息。`model_attempts` 与结构化上下文清单不依赖面板开关，始终按既定规则记录，避免问题发生后无证据可查。
- 完整记录：面板内另设默认关闭的“记录完整上下文”开关，只在服务端开发者门禁开启时有效；开启前明确提示包含本局私有信息，仅对当前服务会话生效，服务重启自动关闭。开启后允许在面板中查看完整 Prompt/原始响应，但每条记录必须再次确认才展开，并继续过滤 Key、Base URL 和请求头、遵守 7 天与容量上限。
- 原因：让信息隔离从“相信 Prompt 写对了”提升为调用前可阻止、调用后可追溯和可在面试中展示的工程证据，同时控制新增观测面本身的泄漏风险。

## DEC-096 轻量模型熔断与可选观测平台

- 日期：2026-08-19
- 状态：已确认，已实现（第三方适配器仍为可选扩展）
- 轻量熔断：同一 Provider 的 `401/403`、模型不存在等确定性配置错误立即阻止后续无意义调用；网络、429 和 5xx 仍先沿用现有有限重试，短时间连续失败达到阈值后暂停新请求一段可配置的短冷却时间，之后只放行一次探测请求决定是否恢复。
- 在途边界：已经发出的模型请求允许正常结束；熔断等待和状态变化进入脱敏调用台账与调试面板，但不伪装为 Agent 内容错误或玩家违规。
- 当前模型：不改变已通过真实验收的三个参赛模型现有超时、并行方式和重试流程；本轮不新增统一动作总时间预算，也不基于未知模型自动猜测超时或推理参数。
- 自有语义：错误分类、链路 ID、上下文边界、`model_attempts` 和审计规则由项目 Harness 定义，复用 DEC-086 的稳定错误分类；第三方平台不能替代这些业务契约。
- 扩展方式：抽象可选 `TelemetrySink`，默认写入本地 SQLite 与审计文件；未来可适配第三方观测平台，但默认不联网、不要求额外 Key，也不向外部发送完整 Prompt、词牌或私有信念。
- 实施顺序：先贯通链路 ID、`model_attempts`、结构化上下文清单、脱敏与调用前门禁；再实现熔断、服务中断恢复、复盘调度和 SQLite 可靠性；随后补浏览器 SSE/命令恢复；最后接入双层门禁的开发者面板。先保证观测事实可信，再让恢复逻辑和界面消费这些事实。
- 原因：用较小实现成本阻止并行 Agent 在同一故障中持续冲击中转站，同时保留本地可运行、供应商中立和信息隔离的交付特性。

## DEC-097 系统审计后的 Agent 工程补强

- 日期：2026-08-19
- 状态：已确认，已实现
- 上下文来源：参赛 Agent 的输入必须由唯一的服务端上下文组装器从权威仓库读取。组装结果携带与具体输入绑定的来源证明，至少覆盖 game、actor、私有信念所有者、公开事件可见性和公开游标；调用前门禁不得只相信调用者手写的来源声明。
- 标识唯一性：信念概率列表和复盘逐 Agent 评价必须拒绝重复 `playerId`，不能只用集合覆盖判断间接接受重复项。
- 复盘契约：提示词中的字数、关键片段数量和必填字段必须与共享 Zod Schema 一致，避免模型遵循提示词却被 Schema 拒绝，或 Schema 接受明显偏离产品要求的结果。
- 后台异常：后台推进遇到未分类程序异常时必须进入既有运行中断恢复状态，不能只记录日志后让页面永久停留在“AI 思考中”；该路径不得归责为模型失败或消耗模型重试预算。
- 尝试阶段：Provider 响应成功、结构校验通过、内容校验通过和领域动作提交是不同阶段。观测记录不得在内容或领域校验前宣称最终成功；开发者面板应能区分请求成功与动作最终落地。
- 运行门禁：仓库固定 Node 22 LTS 作为已验证运行时，并增加只使用假模型、零网络密钥、零付费调用的 GitHub CI；真实模型验收继续保持人工显式触发。
- 范围排除：负责人明确接受零宽字符可能绕过直接原词匹配的残余风险，本轮不增加 Unicode 归一化规则；不改变 DEC-096 已确认的模型超时、并行、重试与统一动作预算边界。
- 提交规则：TASK-078～083 每完成一个独立问题，分别验证并形成一个 Git commit；本轮不自动推送远端。
- 原因：优先补齐能够直接提升信息边界证明、故障可恢复性和 Agent Harness 可解释性的工程缺口，同时保持单机面试项目的合理规模。
